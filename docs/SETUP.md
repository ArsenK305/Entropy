# Подключение GPT-6.1 Sol к Entropy

## Подготовка PostgreSQL

Для локальной разработки Entropy использует отдельную базу `entropy_dev` и роль приложения `entropy_app`. Не используй администратора PostgreSQL для запуска приложения.

1. В корне проекта открой Terminal в PyCharm и выполни `python -m pip install -r requirements.txt`.
2. Убедись, что служба PostgreSQL запущена. В PowerShell (в том числе терминале PyCharm) задай подключение для миграции:

```text
$env:ENTROPY_DATABASE_URL = "postgresql+psycopg://entropy_app:ТВОЙ_URL_ENCODED_ПАРОЛЬ@127.0.0.1:5432/entropy_dev"
python -m alembic upgrade head
```

Подставь пароль роли приложения, не пароль администратора. Если в пароле есть символы `@`, `:`, `/`, `#` или `%`, закодируй их для URL (например, `@` как `%40`). Не отправляй строку подключения и не добавляй её в Git. Команда создаст пустую схему Entropy в `entropy_dev`; прежняя SQLite-база не импортируется и не удаляется. Без `ENTROPY_DATABASE_URL` миграции намеренно откажутся запускаться, чтобы случайно не менять старую SQLite-базу.
3. В **Run → Edit Configurations… → Environment variables** конфигурации `app.py` добавь ту же переменную `ENTROPY_DATABASE_URL`. Переменная из терминала сама по себе не попадёт в конфигурацию запуска.
4. Запусти `app.py`. Для локальных тестов без PostgreSQL можно не задавать `ENTROPY_DATABASE_URL`: тогда используется локальный `data/entropy.db`.

Для проверки состояния миграций используй `python -m alembic current` и `python -m alembic history`. Новые изменения структуры оформляй новой миграцией в `migrations/versions/`; не редактируй уже применённую ревизию.

## Подключение OpenAI

Entropy работает в бесплатном локальном демо по умолчанию. Реальный режим включается только через переменные окружения запуска приложения.

## 1. Включи оплату API и поставь ограничение

1. Открой [API Platform](https://platform.openai.com/) и войди в аккаунт.
2. В разделе Billing добавь способ оплаты или пополни API-баланс. Подписка ChatGPT и API оплачиваются отдельно.
3. Для нового prepaid-аккаунта минимальное первое пополнение сейчас $5. При настройке проверь Auto-reload и выключи его, если не хочешь автоматических повторных списаний.
4. Создай отдельный API project для Entropy. В его Limits настрой уведомление и, если доступно, жёсткий лимит расходов. Уведомление само по себе не всегда останавливает запросы.
5. На странице проекта открой API Keys → Create new secret key. Скопируй ключ сразу: позднее платформа не покажет его повторно.

## 2. Добавь ключ в конфигурацию запуска PyCharm

1. В PyCharm открой **Run → Edit Configurations…**.
2. Выбери конфигурацию, которая запускает `app.py` из корня проекта. Если её ещё нет, создай Python-конфигурацию с Script path `app.py` и Working directory = корень `Entropy`.
3. В **Environment variables** добавь:

```text
ENTROPY_MODE=live
ENTROPY_MODEL=gpt-6.1-sol
VELTRICS_MODEL=gpt-6.1-sol
ENTROPY_REASONING_EFFORT=low
ENTROPY_MAX_OUTPUT_TOKENS=1200
VELTRICS_MAX_OUTPUT_TOKENS=800
OPENAI_API_KEY=твой_секретный_ключ
```

Никому не отправляй секретный ключ и не вставляй его в Python-код, сообщения, скриншоты или Git. В этом проекте `.idea/` и `.env` игнорируются Git.

## 3. Запусти приложение

Нажми Run в PyCharm. В окне Run должно появиться `Mode: openai-live; model: gpt-6.1-sol`. Открой <http://127.0.0.1:8765>. Верхний индикатор покажет подключённую модель.

Если вернёшь `ENTROPY_MODE=demo` или удалишь эту переменную, Entropy снова будет работать без платных API-вызовов. Если выбран `live`, но ключ не задан, приложение остановится с понятным сообщением.

## Что умеет live-режим сейчас

- Сначала делает один вызов Entropy для ответа и решения, нужна ли подзадача Veltrics. Обычный разговор требует один вызов; делегированная техническая задача — два.
- Модели ролей настраиваются отдельно: `ENTROPY_MODEL` и `VELTRICS_MODEL`. Сейчас обе по умолчанию используют GPT-6.1 Sol; это разделение позволит позже независимо сменить модель роли.
- Передаёт обоим ролям `AGENTS.md`, устав и brief MVP, краткое текущее состояние `LEARNING.md` и до 12 предыдущих реплик этого же диалога; Veltrics также получает план Entropy.
- По умолчанию ограничивает генерацию 1200 выходными токенами для Entropy и 800 для Veltrics. Жёсткие пределы задаются через `ENTROPY_MAX_OUTPUT_TOKENS` и `VELTRICS_MAX_OUTPUT_TOKENS` (16–100000). В меню «Токены» пользователь может выбрать лимит от 300 до предела окружения без перезапуска; если предел окружения ниже 300, минимумом становится он. Значение передаётся Responses API как `max_output_tokens` на каждый вызов. Настройка сохраняется в браузере. Это верхний предел одного ответа, включая токены рассуждений, а не целевой объём или общий денежный лимит API.
- Очень низкий лимит может оборвать JSON-маршрутизацию до того, как модель сформирует решение; Entropy теперь помещает флаг передачи первым и восстанавливает явный handoff из частичного ответа. Если даже флаг не появился, он сообщает об обрыве вместо ложного подтверждения передачи. Для сложного ответа или кода нужен больший лимит.
- Не предоставляет модели доступ к репозиторию, локальным файлам или внешним инструментам. Veltrics может подготовить код прямо в ответе, но сам не записывает его в проект.
- Сохраняет диалоги и задачи в PostgreSQL, если задан `ENTROPY_DATABASE_URL`; иначе использует локальный `data/entropy.db`.
- Интерфейс обновляет состояние раз в 5 секунд, пока вкладка видна; запросы локальные и не вызывают модель. События задачи опрашиваются только пока она выполняется.
- Переход на чистый `/` открывает новый пустой диалог, сохраняя прошлый в истории; перезагрузка `/#chat` восстанавливает активный диалог. На Windows новый чат также открывается по `Ctrl+K`.

## Вкладка поиска работы

- В боковой панели открой **Поиск работы** и вставь текст вакансии. Каждый разбор получает отдельный диалог в списке «Недавние разборы»; старые беседы можно открыть оттуда. Карьерный профиль `data/career_profile.md` остаётся локальным.
- `data/entropy_memory.md` хранит общую непрерывность между диалогами; `data/career_profile.md` хранит карьерный профиль и подключается только в этом модуле. Оба файла исключены из Git правилом `/data/` и редактируются локально.
- В live-режиме память передаётся модели в каждом запросе, а карьерный профиль — только запросам из вкладки поиска работы; оба расходуют API usage.
- Страница вакансии по одной ссылке пока автоматически не загружается: вставь описание вакансии вместе со ссылкой. Модуль оценивает и готовит черновик, но не отправляет отклики и не связывается с работодателями.
- Вкладка расходует API usage в live-режиме так же, как обычный диалог. Сам файл профиля остаётся локальным, но его содержимое вместе с вакансией передаётся выбранной модели для каждого анализа.

## Frontend: React, TypeScript и Vite

Исходники интерфейса находятся в `frontend/`. Python API и база данных остаются самостоятельным backend.

1. Установи Node.js LTS с [официальной страницы Node.js](https://nodejs.org/en/download). Установщик включает Node.js и npm. После установки закрой и заново открой терминал. В папке `frontend` выполни `npm install`.
2. Для разработки запусти Python-сервер на `127.0.0.1:8765`, затем в отдельном терминале из `frontend` запусти `npm run dev`. Vite откроет интерфейс на `http://127.0.0.1:5173` и проксирует `/api` на Python.
3. Чтобы локальный Python-сервер отдавал новый интерфейс, из `frontend` выполни `npm run build`, затем перезапусти Python-сервер. Собранные файлы в `entropy_app/static/dist/` являются артефактами и не хранятся в Git.
4. `npm run typecheck` проверяет типы без сборки.

## Telegram Mini App и Argus — контрольная точка видео-демо

Витрина доступна только по отдельному адресу Mini App `/miniapp`; перехода к ней из сайта Entropy нет. В тестовом заказе нет Stars и реальной выдачи продукта.

### Локальный просмотр без бота

1. В Run Configuration для `app.py` задай `ENTROPY_MINIAPP_PREVIEW=1`. Этот режим принимает заказ только из локального браузера с origin `127.0.0.1`, `localhost` или `::1` на порту 5173/5174/8765. Не включай его при публикации или запуске HTTPS-туннеля.
2. Примени миграцию `0002_orders_and_observability` командой `python -m alembic upgrade head` с той же `ENTROPY_DATABASE_URL`, что используется приложением.
3. Запусти `app.py` в PyCharm и Vite из `frontend`: `npm run dev`.
4. Открой `http://127.0.0.1:5173/miniapp?preview=1` (или `5174`, если Vite выбрал следующий порт), создай тестовый заказ, затем открой `/argus`. Заказ и события сохраняются в базе; user ID Telegram в preview не сохраняется.

### Подключение Mini App к боту

1. Добавь полученный у BotFather токен как `TELEGRAM_BOT_TOKEN` только в Run Configuration `app.py`. Выключи `ENTROPY_MINIAPP_PREVIEW`.
2. Укажи в BotFather публичный HTTPS URL с путём `/miniapp` как Main Mini App или Menu Button. Локальный адрес `127.0.0.1` Telegram-клиенту недоступен; для ручной проверки нужен HTTPS-туннель или хостинг.
3. Так как Mini App вызывает API по относительному `/api`, фронтенд и backend должны быть доступны с одного HTTPS origin (например, через reverse proxy или сборку Vite, которую отдаёт `app.py`). Не указывай в BotFather отдельный static URL, если он не маршрутизирует `/api`.
4. Mini App передаёт сырой `Telegram.WebApp.initData` на backend; backend проверяет подпись и срок действия. `initDataUnsafe` не используется. Данные Telegram-пользователя сейчас не сохраняются и не отправляются в n8n, поскольку оплата и выдача товаров ещё не реализованы.

### Подключение n8n и события Argus

- `ENTROPY_N8N_WEBHOOK_URL` — production URL активного узла Webhook, принимающего POST заказа. Backend сначала сохраняет заказ и событие, затем синхронно отправляет webhook с timeout 5 секунд. Настрой узел на быстрый ответ «принято», а обработку продолжай после ответа; если URL не задан или вызов не прошёл, запись заказа сохраняется, а Argus показывает ожидание/ошибку. Автоматических повторов пока нет.
- Payload содержит `event: order.created`, `correlation_id` (ID заказа), данные тестового продукта и `mode: demo_no_payment`.
- Чтобы показывать этапы workflow, настрой в n8n HTTP Request callback на `POST /api/observability/events`. Передай заголовок `X-Entropy-Event-Token`, совпадающий с `ENTROPY_N8N_EVENT_TOKEN`, и JSON `{ "correlation_id": "<order-id>", "source": "n8n", "event_type": "workflow.started", "status": "running", "detail": "Workflow начал обработку" }`. Для завершения отправь `workflow.completed`/`completed`; для ошибки — `workflow.failed`/`failed`. Агентские события используют `source` `psyche`, `ophira` или `veltrics` и тот же correlation ID.
- Argus читает сохранённые события через `GET /api/observability/events` и обновляет экран раз в 4 секунды. `n8n_configured` означает только, что URL задан; доступность n8n проверяется фактической отправкой заказа.
- Если n8n работает в Docker, адрес `127.0.0.1` внутри контейнера указывает на контейнер. Callback должен использовать адрес backend, достижимый из контейнера. Для n8n Cloud callback backend должен быть публично доступен.

Локальный backend по умолчанию слушает только loopback. Перед публичным размещением нужно добавить авторизацию для Argus API и ограничить доступ к диагностическим событиям. HTTPS-домен не нужен для локальной цепочки; он понадобится для запуска Mini App из Telegram, а публичный webhook нужен внешнему сервису, который должен сам вызывать backend.

GPT-6.1 Sol сейчас стоит $2 за 1 млн входных токенов и $10 за 1 млн выходных токенов в стандартном режиме. Фактическая цена зависит от длины контекста и ответа; делегирование добавляет второй вызов.
