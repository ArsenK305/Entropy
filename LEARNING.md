## Журнал архитектурных решений

| Решение | Почему и альтернативы | Компромисс / когда пересмотреть |
|---|---|---|
| SQLAlchemy Core с миграциями Alembic; PostgreSQL для локального приложения и SQLite для изолированных тестов | Единый интерфейс запросов, управляемая история схемы и практический PostgreSQL без ORM-слоя, который проект пока не требует | Добавлены зависимости и миграционный шаг перед запуском; пересмотреть SQLite в тестах при появлении PostgreSQL CI или специфичных запросов |
| Demo по умолчанию; live Responses API включается настройкой | Не расходовать API-бюджет при локальном запуске и явно отделить демонстрацию от реальной модели | Две модели ролей пока работают через один API-адаптер; для Codex или другого провайдера понадобится отдельная интеграция |
| Entropy отвечает сам и делегирует Veltrics только техническую работу | Обычный диалог не создаёт лишнюю задачу разработчику | Классификатор маршрута пока основан на одном вызове LLM; нужен тестовый набор и проверка ошибок формата |

## Как планировать работу с Kars

- Держать план конкретным и ограниченным: до трёх приоритетов на день, с видимым результатом для каждого.
- Не превращать пропущенный день в долг и не считать идею выполненным прогрессом. Отделять ближайший полезный шаг от дальнейших желаний.
- Если план начинает разрастаться, проверять его по текущим срокам, энергии и фактической цели; прямо отмечать, что сейчас лишнее.
- Подготовку к собеседованиям включать отдельным ограниченным блоком, сохраняя основной фокус на проекте, когда Kars этого хочет.
